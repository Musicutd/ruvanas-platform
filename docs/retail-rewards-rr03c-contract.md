## Frozen local semantics

Authenticated shoppers claim a reviewed published revision at one deliberately public shop. A claim is one use; REUSABLE offers allow subsequent fresh claims subject to aggregate limits. Expiry=min(issue+24h, issued offer end, current membership expiry). No inventory reservation/purchase guarantee: successful redemptions alone consume limits. One unexpired unredeemed claim per shopper+offer at a time, across revisions/shops; same target/revision returns it, other target/revision conflicts. Creation requires expectedRevision and UUID idempotencyKey. Changed key payload conflicts; same retry returns original claim after current shopper authorization, never issues another.

Claims permanently pin exact offer revision, selected location and public shop name/slug. Later offer edits do not rewrite issued terms. Cancellation blocks redemption. PAUSED uses issued pausedClaimsPolicy; PUBLISHED can honour issued older revisions. No current discovery opt-in is required for issued redemption (withdrawal blocks new claims). Current active merchant Retail/Rewards access, active shop, ACTIVE shopper/current unrevoked internal membership and matching shopper authVersion are still required. Shopper logout/session expiry does not itself cancel an issued claim; issuing/rotating credentials requires an authenticated current shopper session. No grace-period or offline bypass. Current feature disablement blocks all checkout operations.

Offer total, per-shopper lifetime and daily caps count all immutable successful receipts with that stable offerId across all revisions and shops. Use issued terms' caps, not a newly edited draft; published tightening affects future claims, not prior issued terms. SINGLE_USE per-shopper and daily caps are1; totalLimit remains the configured offer capacity. Daily calendar is fixed by RewardOfferUsagePolicy.timezone at first claim; new claims reject an offer whose terms timezone differs. Count old receipts by occurredAt in this stable calendar, not stored revision-specific dates. Monthly business quota is the current grant's monthlyRedemptions in UTC calendar month and covers all the organisation's offers. Claims do not reserve these capacities. Serialize all checkout writes on RewardProgram first, sharing lock ordering with offer editing, then offer and exact identity/authority rows. Recheck current time and authority before commit. SERIALIZABLE bounded retries and unique claim receipt establish exactly-once.

Each claim has an authenticated POST credential operation generating random32-byte lowercasehex token, HMAC-SHA256 with the domain below, stored hash only, expires=min(now+5min,claim expiry). Reissuing rotates/invalidate previous token. Token domain `ruvanas-rewards-checkout:v1:` with SESSION_SECRET>=32. Never a URL, query, log, browser storage or ordinary claim ID used as bearer. Shopper code shown only in memory; manual paste works. QR/scanner, reversal/refund and reporting are later work.

Staff validate is advisory: no consumption or reservation. Redeem independently repeats checks under locks. Body includes qualifying purchase amount in integer minor units, matching currency and explicit termsConfirmed:true. Staff attests exclusions, BOGO and other terms; no POS verification is claimed. Enforce minimumSpendMinor; percent saving=floor(eligibleSpendMinor*percentBps/10000), fixed saving=min(eligibleSpendMinor,amountMinor), BOGO saving=null (quantities displayed, staff applies). Confirmation records an immutable coupon receipt, not a payment or proof of purchase.
