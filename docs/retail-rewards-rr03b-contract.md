# RR-03b private shopper sign in

Local unpublished candidate following the request to continue. All Rewards flags default off, public registration stays closed, no live accounts, invitation delivery, encoders, costs, plans or other channels change. Preserve RR03a. This milestone provides acceptance of a preprovisioned private invitation, password sign-in and shopper-only sign-out. It does not provide invitation issuance/admin provisioning, mailbox verification, recovery, public signup, payments, coupon claims or redemption. Synthetic fixtures provision only explicit disabled shoppers with an active internal membership. An invitation proves possession of that invitation, not verified ownership of an email address.

## Ownership and schema

Database agent owns schema, additive migration137 (20261214000000_retail_rewards_shopper_auth), isolated DB harness/tests, CI/reset compatibility. Service agent owns shopper-auth-service.mjs and focused tests. UI agent owns ShopperAuthClient, CSS, UI tests, synthetic preview and auth pages/ShopperDiscoveryClient sign-out integration. Root owns contracts, HTTP/server/API routes and built HTTP checks.

- RewardShopperCredential: shopperId PK Restrict FK, emailCanonical unique varchar254, passwordHash varchar60 (bcrypt cost12 only, $2a$/$2b$ prefix), createdAt/updatedAt finite. No User/org/Subscription link. Email supported ASCII subset, trimmed/lowercase; validate with the shared canonicalEmailSchema.
- RewardShopperInvitation: id PK, shopperId UNIQUE Restrict FK, emailCanonical UNIQUE varchar254, tokenHash UNIQUE64lowerhex, authVersion>=1, createdAt, expiresAt<=created+24h, revokedAt/acceptedAt nullable. Finite date ordering; acceptedAt>=created and<expires. Default unaccepted; no backfill. Previously consumed tokens cannot be reused by the service. Invitation and credential email identity are separate from business User.email.
- RewardShopper inverse relations credential and invitation. Membership unchanged (MANUAL_INTERNAL only). Global shopper rows survive merchant reset; no new audit action using business actor IDs. No raw passwords/tokens in DB, output, URLs, browser storage or logs.

## Service and transport

Root shopper-auth-contracts.mjs exports readShopperAuthPolicy(env), canonicalEmailSchema, shopperPasswordSchema, acceptShopperInvitationSchema, shopperLoginSchema. Exact RUVANAS_RETAIL_REWARDS_SHOPPER_AUTH_ENABLED=true plus valid enabled main+shopper gates required. Password at least15 Unicode codepoints, max72 UTF8 bytes, no NUL or malformed surrogate, no normalization/trimming. No imposed symbol/uppercase composition. bcryptjs existing dependency cost12, valid dummy comparison for missing account. OWASP references: https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html and https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html . No new dependency download.

createShopperAuthService({db,env,clock}) returns acceptInvite({token,password,displayName?}), login({email,password}), logout({token}). Export hashShopperInvitationToken(token,secret) using64lowerhex token, secret>=32, HMAC domain ruvanas-rewards-shopper-invitation:v1:. Return success {ok:true,rawSessionToken,expiresAt} internally only for accept/login; logout {ok:true}. Safe generic errors {ok:false,status,code,error}: invalid credentials/disabled/expired/missing account uniformly401 AUTH_FAILED; unavailable/used/expired/collision invite uniformly400 INVITATION_UNAVAILABLE; malformed input400 INVALID_REQUEST; disabled403 FEATURE_DISABLED; unexpected503 UNAVAILABLE. Root JSON never returns rawSessionToken, ids or hashes.

Hash/compare outside transaction. Accept must serializably lock/re-read exact invitation, DISABLED shopper/no credential and current ACTIVE unrevoked MANUAL_INTERNAL membership, compare authVersion, then consume invitation, create credential, activate shopper and issue fresh session atomically. Browser cannot supply email/identity/role/membership. Login compares only shopper credential then locks/rechecks credential hash, shopper/version and membership before minting session. Fixed lock ordering, bounded serializable retries. Recheck time after expensive work and before commit; expiry=min(now+24h,membership.expiresAt). No stale authority from preflight. Logout revokes only the token's matching shopper session (even expired), is idempotent for absent/malformed token; no business cookie/logout or global version change.

POST /api/rewards/auth/invitation, /login, /logout. Root adapter validates canonical Origin using existing rewardsMutationOriginAllowed plus Sec-Fetch-Site; strict JSON with an8192-byte streaming limit; reject query params/unknown body fields. Rate-limit IP before expensive work (20/15min) and identity keyed by canonical email or hashed invite token globally (10/15min), no stored raw identity. Logout IP-only. Cookie ruvanas_rewards_shopper, HttpOnly, Secure in production, SameSite=Lax, Path=/, absolute expiry bounded above. Return fixed next=/rewards (no user redirects). Disabled endpoints no DB/hash; no signup route or middleware broad exemption. Both API and page gated. /rewards/sign-in and /rewards/accept-invitation never consume a token on GET. No token query/hash parsing. /rewards denied page links to private sign-in only if auth flag enabled. Sign-out clears shoppercookie only after successful revocation (if disabled, clear cookie locally without database access).

## UI and verification

The HTTP success destination is fixed to `/rewards` for invitation acceptance and login, and `/rewards/sign-in` for logout. The current discovery UI returns to `/rewards` after successful logout, where the gated sign-in link is available; it does not follow a user-supplied destination.

ShopperAuthClient props mode=login|invitation, transport optional, onSuccess optional, previewOnly=false. Login inputs email,password; invitation inputs token,password,confirmPassword,optional displayName; only token/password/displayName sent to API. No secret persistence, clipboard reads, external fonts or automatic sign-in. On success replace location with fixed/rewards unless injected preview callback. Clear passwords/token after completion; readable generic errors and a no-public-signup notice. Preview uses only sample credentials and local memory transport, clearly labelled; existing63847 preview stays intact.

Require unit/HTTP isolation and CSRF/body/rate/cookie tests, fresh137 and136→137 migration with no old data changes, real concurrent replay/revocation/rollback tests, distinct business-cookie semantics, expired membership/session, logout and failed-login generic responses. Build, actual local HTTP activation→login→discovery→logout and mobile preview. No production deployment or activation; release CI and production migration preflight remain separate gates.
