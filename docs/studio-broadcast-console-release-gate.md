# Studio Basic + Pro + Broadcast Console local release gate

This is a local implementation checkpoint against fetched `origin/main` `6656757a2f9ead6d693b8e3262a2fdae395818fa`, not publication approval. The branch incorporates that main commit through a **local-only merge**. No push, pull request, remote merge or deploy was performed.

## Reuse and implementation

The existing six-product, thirty-plan catalogue, shared Studio entitlement, Waveform/Multitrack editors, Manual Playout, Radio Clocks, Voice Tracking, Browser Live Studio, scheduler, AutoDJ, protected media, rights checks, destination profiles and worker were reused. The STP.0 matrix is in `studio-broadcast-console-stp0-audit.md`.

Locally added: a Pro-only Broadcast Console tab and read-only second-screen monitor; presenter layout preferences; a Daily Log projection that keeps scheduled items and verified proof-of-play separate; scoped presenter notes; scoped hot-cart banks and media references; broadcast mix-point storage, validation and preparation defaults; channel/output-health summaries. The Console uses existing Studio access and product entitlements. It does not fire carts, launch microphone capture, or send an item to public output. The latest main's guarded Online Radio Centova worker is a separate output path for its AutoDJ rotation, not the Studio Manual Playout bridge.

This continuation adds a fail-closed output boundary: Manual start/skip/fade and Studio Broadcast start return a conflict until a verified Studio queue-to-player/encoder bridge exists. Queue preparation remains available; it rechecks product use, ownership, media status, catalogue tier, rights approval, licence window and known channel territory. Restricted-territory music is not represented as ready when territory is unknown. Console and playout sessions, carts and managed stations are constrained to the active product family. Studio destination monitoring keeps legacy connections in standby and does not claim listener or metadata output from a healthy Centova source alone. The Console and Studio screens explain the boundary instead of presenting queue state as proven output.

The next local increment makes the presenter workspace a controlled preparation surface: it sends approved Prepare items to Next or the future queue through the existing Manual Playout API, and reorders/locks future items with idempotency keys and optimistic revisions. Dense ordering is computed server-side, played items cannot move, and a locked future item cannot be crossed or displaced by Send to Next. The read-only second-screen monitor still cannot issue commands. The Daily Log now warns when the preceding planned item may overlap a fixed event. None of these controls starts public audio.

The current local continuation adds a private Liquidsoap command-socket transport boundary for prepared Studio audio (`lib/studio-encoder-transport.mjs`). It accepts only a real, local protected media file and a socket in the same private encoder cache; the command response is explicitly classified as a queue acknowledgement, **not listener proof**. It is intentionally not wired to the running Online Radio worker or exposed to web requests. The worker's existing Centova AutoDJ path is unchanged, and Manual/Broadcast live controls stay blocked. Before wiring this transport, an encoder build must expose a restricted Unix socket, arbitrate emergency/live/schedule/campaign/Manual/AutoDJ priority, recheck rights immediately before each output, consume encoder output events, and correlate independently sampled listener audio. The Debian Bookworm image uses Liquidsoap 2.1.3, so syntax and event semantics must be verified against that exact installed binary in an isolated container; that executable is unavailable in this Windows worktree.

The following local increment adds `planStudioOnlineOutput`, a **dry-run** handoff decision built on the existing unified playout resolver. Manual sits below emergency, live, school and programme sources and above AutoDJ. The plan refuses a handoff without the station worker lease, a current same-tenant Online Radio/Studio Pro session and fallback, a fresh complete scheduling snapshot, a rights-current protected item for the correct product/territory/source scope, or enough licence time to play the whole source. It also refuses required insertions and unsupported cue/fade/gain processing. This function does **not** change the worker, queue media, assert listener proof, or unlock live Console commands. Applying the decision in the actual encoder remains separate work.

The next local increment adds `loadStudioOnlineAuthority`, a read-only station/channel-scoped snapshot using a repeatable-read database transaction. It compiles current and upcoming published programme occurrences (including overnight slots) as protected candidates and fails closed on malformed or multiple active versions. Station/channel-targeted campaigns, active radio advertising, player insertions, physical channel assignments, imported syndication, live failover, external live sources and Browser Live sessions block the snapshot until each has a real Centova output adapter. Physical-location campaigns do not cross into Online Radio. The snapshot declares its covered interval; the dry-run handoff rejects a snapshot that ends before the entire protected audio file. The snapshot is **not used to control live output**, and an empty snapshot is not a listener-output acknowledgement. A future live adapter must also re-read policy and rights after the snapshot and preempt output when a protected source changes; a ten-second snapshot age alone cannot guarantee an uninterrupted programme.

The latest local increment adds an **opt-in read-only shadow check** to the existing Online Radio encoder worker (`RUVANAS_STUDIO_HANDOFF_SHADOW=1`; off by default). After a successful AutoDJ lease renewal, it re-reads the current lease and one tenant/channel-scoped active Manual session, its first prepared LIVE item and protected media, then asks the authority snapshot and dry-run planner whether a handoff would be eligible. It emits only a changed diagnostic reason, not item metadata, a source command or listener proof. A failed diagnostic does not stop AutoDJ. The snapshot and media are not read atomically together, so even a positive diagnostic cannot authorize a live handoff. No Render setting is changed locally; no production worker is running this opt-in check yet.

The isolated Centova acceptance boundary is documented in `studio-isolated-centova-acceptance.md`. A local, network-free target validator rejects the known Radio Test 105 listener/source and any caller-supplied current production endpoints before a future test may use a distinct stream. This only checks configuration: no separate test stream, Liquidsoap/container or disposable database is attached here, and no source switch or listener recording was executed.

The new migration is `20261120000000_studio_broadcast_console`. It adds five small reference/configuration tables: `StudioConsolePreference`, `StudioCartBank`, `StudioCart`, `StudioMixPoint`, and `StudioPresenterNote`. It does not duplicate media bytes, the scheduler, playout, broadcasting, or proof tables.

## Incomplete acceptance and release blockers

1. **Manual output bridge:** existing Manual Playout transitions are not consumed by the player resolver/manifest. `ON_AIR` in the server queue is not evidence of listener output. Integrate a priority-aware, server-authoritative output path, then prove that scheduled, emergency and campaign events interrupt/resume safely and empty queues return to AutoDJ.
2. **Transport:** external Icecast/SHOUTcast profiles require a configured compatible encoder provider. Browser Live microphone output requires its real-time provider. Neither is available in this local workspace. No external destination or microphone delivery was tested.
3. **Console completeness:** live hot-cart firing, direct microphone controls, fully adjustable panels, visual Radio Clock drag/reorder with conflict warnings, in-context Voice Tracking handoff, sponsor/spot board, and future-only Daily Log edits are not complete. The Console links to existing Radio Clock, Voice Tracking and Browser Live workflows rather than duplicating them.
4. **Rights and output proof:** preparation now re-evaluates music eligibility, but a live output bridge must repeat this immediately before output, including territory, catalogue tier, licence window and takedowns. The applicable channel territory must be established for restricted music. Planned Daily Log entries never count as verified plays.
5. **End-to-end acceptance:** no disposable PostgreSQL, streaming provider or player fleet is attached to this worktree. Schema and build can be validated locally; migration apply, tenant/role flows, actual playback, fallback, destination reconnect and downgrade tests need an isolated environment.
