# Studio Basic + Pro + Broadcast Console local release gate

This is a local implementation checkpoint against fetched `origin/main` `6656757a2f9ead6d693b8e3262a2fdae395818fa`, not publication approval. The branch incorporates that main commit through a **local-only merge**. No push, pull request, remote merge or deploy was performed.

## Reuse and implementation

The existing six-product, thirty-plan catalogue, shared Studio entitlement, Waveform/Multitrack editors, Manual Playout, Radio Clocks, Voice Tracking, Browser Live Studio, scheduler, AutoDJ, protected media, rights checks, destination profiles and worker were reused. The STP.0 matrix is in `studio-broadcast-console-stp0-audit.md`.

Locally added: a Pro-only Broadcast Console tab and read-only second-screen monitor; presenter layout preferences with visible-panel, width, keyboard move-order and settings-handle drag controls; a Daily Log projection that keeps scheduled items and verified proof-of-play separate; scoped presenter notes; scoped hot-cart banks and media references; broadcast mix-point storage, validation and preparation defaults; channel/output-health summaries. The Console uses existing Studio access and product entitlements. It does not fire carts, launch microphone capture, or send an item to public output. The latest main's guarded Online Radio Centova worker is a separate output path for its AutoDJ rotation, not the Studio Manual Playout bridge.

This continuation adds a fail-closed output boundary: Manual start/skip/fade and Studio Broadcast start return a conflict until a verified Studio queue-to-player/encoder bridge exists. Queue preparation remains available; it rechecks product use, ownership, media status, catalogue tier, rights approval, licence window and known channel territory. Restricted-territory music is not represented as ready when territory is unknown. Console and playout sessions, carts and managed stations are constrained to the active product family. Studio destination monitoring keeps legacy connections in standby and does not claim listener or metadata output from a healthy Centova source alone. The Console and Studio screens explain the boundary instead of presenting queue state as proven output.

The next local increment makes the presenter workspace a controlled preparation surface: it sends approved Prepare items to Next or the future queue through the existing Manual Playout API, and reorders/locks future items with idempotency keys and optimistic revisions. Dense ordering is computed server-side, played items cannot move, and a locked future item cannot be crossed or displaced by Send to Next. The read-only second-screen monitor still cannot issue commands. The Daily Log now warns when the preceding planned item may overlap a fixed event. None of these controls starts public audio.

The current local continuation adds a private Liquidsoap command-socket transport boundary for prepared Studio audio (`lib/studio-encoder-transport.mjs`). It accepts only a real, local protected media file and a socket in the same private encoder cache; the command response is explicitly classified as a queue acknowledgement, **not listener proof**. It is intentionally not wired to the running Online Radio worker or exposed to web requests. The worker's existing Centova AutoDJ path is unchanged, and Manual/Broadcast live controls stay blocked. Before wiring this transport, an encoder build must expose a restricted Unix socket, arbitrate emergency/live/schedule/campaign/Manual/AutoDJ priority, recheck rights immediately before each output, consume encoder output events, and correlate independently sampled listener audio. The Debian Bookworm image uses Liquidsoap 2.1.3, so syntax and event semantics must be verified against that exact installed binary in an isolated container. A later Windows 2.1.3 file-only WAV rehearsal checks a narrower sequencing path; it does not verify this command socket, Debian encoder, MP3 output or listener delivery.

The following local increment adds `planStudioOnlineOutput`, a **dry-run** handoff decision built on the existing unified playout resolver. Manual sits below emergency, live, school and programme sources and above AutoDJ. The plan refuses a handoff without the station worker lease, a current same-tenant Online Radio/Studio Pro session and fallback, a fresh complete scheduling snapshot, a rights-current protected item for the correct product/territory/source scope, or enough licence time to play the whole source. It also refuses required insertions and unsupported cue/fade/gain processing. This function does **not** change the worker, queue media, assert listener proof, or unlock live Console commands. Applying the decision in the actual encoder remains separate work.

The next local increment adds `loadStudioOnlineAuthority`, a read-only station/channel-scoped snapshot using a repeatable-read database transaction. It compiles current and upcoming published programme occurrences (including overnight slots) as protected candidates and fails closed on malformed or multiple active versions. Station/channel-targeted campaigns, active radio advertising, player insertions, physical channel assignments, imported syndication, live failover, external live sources and Browser Live sessions block the snapshot until each has a real Centova output adapter. Physical-location campaigns do not cross into Online Radio. The snapshot declares its covered interval; the dry-run handoff rejects a snapshot that ends before the entire protected audio file. The snapshot is **not used to control live output**, and an empty snapshot is not a listener-output acknowledgement. A future live adapter must also re-read policy and rights after the snapshot and preempt output when a protected source changes; a ten-second snapshot age alone cannot guarantee an uninterrupted programme.

The Online Radio encoder worker has an **opt-in read-only shadow check** (`RUVANAS_STUDIO_HANDOFF_SHADOW=1`; off by default). After a successful AutoDJ lease renewal, it reports only a changed diagnostic reason, not item metadata, a source command or listener proof. A failed diagnostic does not stop AutoDJ. No Render setting is changed locally; no production worker is running this opt-in check yet.

The shadow inspection now runs **without awaiting it in the AutoDJ scan loop**, with at most one inspection in flight. Slow or failed diagnostics cannot hold up lease renewal; shutdown stops new inspections and waits at most five seconds for an in-flight read before closing the database. This remains local, opt-in and read-only. It neither queues Studio media nor alters the protected AutoDJ source.

The local Online Radio rotation now refuses a station with multiple active channels or a channel attached to a different station/organisation, matching the stricter Studio admission boundary instead of arbitrarily choosing the first channel. Its restart fingerprint also includes the **effective approved bitrate** passed to the encoder, so an entitlement-driven bitrate change cannot leave a previously launched encoder running at the old setting. These are fail-closed local worker changes, not a Studio source switch. Before release, check existing station/channel data for any legacy mismatches and verify restart behaviour on an isolated Centova stream.

The Console's Voice Tracking link now opens the existing Production workflow with its selected channel as optional context. The destination preselects that channel only if its tenant-scoped Voice Tracking catalogue returns it; invalid or inaccessible IDs are ignored. The handoff does not create a segue, bypass preview/approval, or change live output. Radio Clock and microphone controls remain separate existing workflows.

The presenter clock and Daily Log planned/estimated times now use the schedule's channel timezone rather than the browser timezone. Each time displays its UTC offset so the repeated hour during a daylight-saving fall-back is distinguishable. Invalid timestamps or timezones display no fabricated time. This corrects presentation only; scheduling and output authorities are unchanged.

Visible panel handles in layout settings can now be dragged onto another panel within the same Console section. The existing preference save persists the new order and widths remain unchanged. Cross-section moves, hidden panels and self-drops are ignored; keyboard move buttons remain the accessible alternative.

The presenter cards now also have their own drag handles. A drop onto another visible card in the same section reuses that layout save; it preserves saved widths and never reorders audio, queues or the programme. Handles are omitted from the read-only monitor and the existing layout-settings arrows remain the keyboard alternative. Local tests check the decision and UI wiring, but authenticated pointer interaction has not been verified in a browser.

The existing Radio Clock draft editor now supports handle-based row reordering with its move-up keyboard alternative. It recomputes each item's planned start and highlights draft hour overruns, invalid overlap lengths and marker/duration conflicts immediately. A reorder only changes unsaved form state and clears the saved preview; the existing draft-save, full-hour preview and owner/manager publish route remain authoritative. The draft editor does not check other programmes or move anything in the live Daily Log.

The Console's read-only Daily Log now treats a published Radio Clock's programme row as a zero-duration boundary when it expands the timed child items, so the hour is not counted twice and intentional within-clock overlaps retain their published offsets. It warns when a clock child crosses a different fixed programme or campaign boundary. Unpublished clock edits are not expanded as if approved. These are planning warnings, not an output-arbitration decision or listener proof; other conflict classes and authenticated browser QA remain open.

The Daily Log now separates its timed programme projection from an explicitly **untimed future Manual queue**. Authorised presenters can move unlocked future Manual items using the existing revisioned/idempotent queue command or explicitly swap an unlocked future organisation-owned music item with a ready item from the private Prepare area. Replacement rechecks the incoming media's product, territory and licence rights in the same transaction, and returns the outgoing item to Prepare; locked, on-air, played, catalogue-owned, promo and other non-music target items are not eligible. This does not edit published schedules, paid spots, fixed events or listener output. Full Daily Log editing, regeneration and isolated browser/database acceptance remain open.

Published timed playlists now project their frozen tracks from the playlist's local-time start, using the same timezone conversion as publication. When the generated sequence matches its published Music Mode programme at that exact start, the programme row becomes a zero-duration boundary instead of double-counting the entire block before its tracks. Intentional generated-track crossfades keep their offsets in the planning view. This only corrects the Console projection; no published schedule, playlist, proof or encoder behaviour changes. Ambiguous/conflicting programmes and real listener timing still require isolated acceptance.

Regenerating a timed playlist creates a newer draft while retaining its prior published version. The Daily Log now reads that published version even when the overall playlist status is `DRAFT`; it excludes never-published, invalidated and archived playlists. The existing player-programming lookup also keeps the published playlist's selected licensed-genre policy while a newer draft awaits review. Planned Log rows no longer default to a fabricated `rightsReady: true` without a rights check. These changes do not publish the draft, alter the worker's Centova source or prove listener output; the Daily Log projection still needs its own authenticated browser and listener-timing acceptance.

The Daily Log now links each visible published timed playlist to the existing Automation workspace, which can reopen a tenant-scoped saved playlist and distinguish published from draft versions. Creating and publishing a first draft still uses the original governed workflow. A duplicate publish of the same version is rejected server-side, including a transactional version claim. A local replacement transaction now creates a new version-specific music mode, preserves the old mode and published schedule history, and replaces only an exact, unique **future** channel programme block or one-day physical-area schedule. Missing, edited or ambiguous originals fail closed; the transaction uses serializable isolation and rechecks track eligibility inside it. A first physical-area publish refuses a competing date-covering schedule. Repeated tracks are deduplicated only for the database music-mode pool, while the full frozen sequence remains in `GeneratedPlaylistVersion.items`. Replacement is **off by default** behind `RUVANAS_TIMED_PLAYLIST_REPLACEMENT_ENABLED=1`, and the Console link remains review-only for existing playlists until authenticated UI and actual output-sequence proof pass. Guarded real-database replacement tests have now passed locally on disposable PostgreSQL for Online Radio, Retail location and Retail zone targets; they do not verify listener audio. The current Online Radio encoder consumes an AutoDJ mode pool, not the timed programme's frozen running order, so this local publisher must not be presented as verified listener playback. The local generator now explicitly labels publication as a programming plan and warns that exact Centova listener output is unverified.

The next local checkpoint revalidates every frozen item inside the publishing transaction against current rights and its planned start/end dates. It also rejects changed duration, genre, source or School explicit-content metadata, and refuses an initial publish after the slot has started. A guarded integration acceptance test covers repeated tracks, same-version duplicate rejection, simultaneous replacement, historic mode/schedule preservation, another-tenant denial, and rollback after an external schedule edit. That test passed against a local app and a fresh, disposable PostgreSQL cluster with the replacement flag enabled only for the test. The public stream and the existing Online Radio worker remain untouched.

For eligible Online Radio accounts with Retail Media access, the Console now shows a read-only commercial spot board. It lists the latest 30 organisation-owned bookings targeted to the selected station or channel, with their existing booking, campaign, inventory, creative and channel-policy statuses. It links back to the governed advertising workspace; it does not compute placement readiness, schedule or fire a spot, or infer listener delivery from approval records. Other product families do not receive this board. No new advertising records or migration were added.

The worker's optional check now uses `loadStudioOnlineAdmission` instead of the older separate-read checker. It reads the station lease, plan entitlement, active Online Radio channel, approved AutoDJ fallback, Manual session and first LIVE item, protected media rights, and scheduling/insertion blockers in one repeatable-read database transaction. It checks snapshot age and rights again after that read. Ambiguous channels/sessions, stale leases, missing rights or incomplete programme authority fail closed. This removes the diagnostic's separate-read inconsistency, but does **not** make a positive result safe to act on: a real output bridge must recheck at the exact switch, react to new protected events and confirm encoder plus listener output. The diagnostic is not wired to the encoder source and does not unlock Manual/Broadcast controls.

The isolated Centova acceptance boundary is documented in `studio-isolated-centova-acceptance.md`. A local, network-free target validator rejects the known Radio Test 105 listener/source and any caller-supplied current production endpoints before a future test may use a distinct stream. This only checks configuration: no separate test stream, Liquidsoap/container or disposable database is attached here, and no source switch or listener recording was executed.

The timed-sequence dry-run now carries the exact published schedule ID, schedule version, programme item ID and priority alongside its frozen track order. A new **read-only authority consistency check** accepts only one fresh matching scheduled-programme candidate at the start boundary, with no competing source or required insertion and no planned audio past the published programme end. This deliberately rejects a generated playlist that overhangs its nominal schedule block, even if generation's tolerance allowed it as a draft/published plan. The first pure check was not loaded in the same transaction as the sequence and is not wired to the worker; it always says `sourceCommandAllowed: false` and `listenerVerified: false`. Output-time rights revalidation, preemption and listener proof remain open.

The read-only `loadPublishedTimedChannelAuthority` diagnostic now loads the frozen version, entitlement, current rights and conflicting station programming within one repeatable-read transaction before applying that strict authority check. It fails closed if the snapshot becomes stale, a protected campaign or live source is uncompiled, the generated audio overruns the programme, or the exact programme identity changes. This removes its separate-read inconsistency but does not make a passing snapshot a live source command: the worker does not call it, and source preemption and listener proof remain unimplemented. A separate later-track diagnostic now rechecks rights and lease at each requested frozen boundary, but it too is not wired to the output worker.

The current local continuation also adds an **offline listener-sample analyser** for distinct self-owned test tones. It reads a local decoded PCM recording and marks one-second windows as AutoDJ, Manual, protected, silent or unknown. It does not fetch a URL, control the encoder or authenticate the origin of the recording; its result explicitly remains `listenerVerified: false`. Only synthetic PCM fixtures have been exercised locally. A real isolated stream capture, manual listening, timing correlation and an output event are still required.

The new migration is `20261120000000_studio_broadcast_console`. It adds five small reference/configuration tables: `StudioConsolePreference`, `StudioCartBank`, `StudioCart`, `StudioMixPoint`, and `StudioPresenterNote`. It does not duplicate media bytes, the scheduler, playout, broadcasting, or proof tables.

## Incomplete acceptance and release blockers

The isolated Centova plan has **six end-to-end scenarios still to execute**: baseline listener audio, Manual takeover, protected-source priority, rights change/takedown, AutoDJ fallback, and failure/reconnect. These are not the same as the passing local unit tests. The five work areas below remain open; several require implementation as well as testing, so there is no credible fixed number of additional unit tests or a deployment date yet.

1. **Manual output bridge:** existing Manual Playout transitions are not consumed by the player resolver/manifest. `ON_AIR` in the server queue is not evidence of listener output. Integrate a priority-aware, server-authoritative output path, then prove that scheduled, emergency and campaign events interrupt/resume safely and empty queues return to AutoDJ.
2. **Transport:** external Icecast/SHOUTcast profiles require a configured compatible encoder provider. Browser Live microphone output requires its real-time provider. Neither is available in this local workspace. No external destination or microphone delivery was tested.
3. **Console completeness:** live hot-cart firing, direct microphone controls, comprehensive cross-programme conflict checks, an embedded Voice Tracking editor, editable sponsor/spot board and full future-only Daily Log edits/regeneration are not complete. The Daily Log can govern unlocked Manual future-queue reorder and a restricted music replacement. It links to review saved timed playlists, but their new duplicate-safe replacement transaction is withheld from the UI pending authenticated UI and listener-output acceptance; the Online Radio and Retail location/zone database replacement cases passed locally. Panel visibility, width and keyboard/drag-handle move-order preferences now work locally, including direct card handles, but authenticated drag QA is pending. The reused Radio Clock draft editor has row dragging and internal timing warnings; the Daily Log shows clock-to-fixed-boundary planning warnings; the Console carries verified channel context into existing Voice Tracking, links to existing Radio Clock and Browser Live workflows, and shows a status-only commercial booking board for eligible Online Radio accounts.
4. **Rights and output proof:** preparation now re-evaluates music eligibility, but a live output bridge must repeat this immediately before output, including territory, catalogue tier, licence window and takedowns. The applicable channel territory must be established for restricted music. Planned Daily Log entries never count as verified plays.
5. **End-to-end acceptance:** a temporary disposable PostgreSQL cluster was used for migration and timed-playlist transaction tests, then stopped and removed. No isolated streaming provider or player fleet is attached to this worktree. Authenticated browser interaction, actual playback, fallback, destination reconnect and downgrade tests still need isolated acceptance.
