# C9 private recording storage inventory — Draft-only

This operator tool is a read-only, bounded evidence report for retained supervised recordings. It is not an orphan-deletion tool, retention policy, release approval, or contributor endpoint. Developing it does not authorise a production inventory. Any real scan needs separately approved database/storage read scope, an authorised operator and restricted report handling. No live storage or customer data was inspected here.

The contributor recording route writes bytes before committing MediaAsset/AudioTake/audit rows. An ambiguous failure now preserves bytes if the database outcome cannot be confirmed. A process death or unavailable database can therefore leave a private object needing staff investigation. Neither the object key nor the existing session/audit records durably pins such an unreferenced object to an exact contributor upload request. This tool cannot recover that missing attribution or safely attach it to a contributor.

## Scope and use

With an approved operator environment, explicitly set `CORRECTIONS_RECORDING_INVENTORY_READ_ONLY=1`, then run `npm run audit:corrections-recordings -- --organisation-id=<approved-id>`. The command validates that opt-in, the selected organisation ID, limit and cursor before loading credentials. It then verifies the organisation exists before listing storage. It has no delete, repair, approval or broadcast mode, and is not connected to the operations worker or any subscriber interface.

Each invocation reads one page under that organisation's `corrections-studio` prefix: default 100, maximum 200 objects. It recognises only direct `<project>/<UUID>.<audio-extension>` recordings, not nested/render paths or arbitrary files. `--limit=<1-200>` changes the page size; `--cursor=<nextCursor>` continues the restricted report's listing. The report always states `BOUNDED_PAGE_ONLY`, even on the last page. An operator must account for all pages and excluded classes separately. Keep the entire report, including opaque continuation tokens, private; tokens come from storage and must not be published to CI logs, PRs or customer pages.

## Evidence and limitations

Exact object references are checked globally and regardless status through MediaAsset, DigitalSignageAsset, ProductionOrderFile and SchoolAudioUploadSession quarantine keys. Cross-tenant and historical anomalies therefore still report `REFERENCED_DB`; no other tenant's row, identity or content is returned. Ordinary downstream takes, clips, renders, promo versions and Corrections evidence resolve recordings through MediaAsset. Project and historical-session existence checks are organisation-scoped and return only bounded project IDs internally; no contributor, programme, facility or session detail is read into the report. Any ACTIVE session conservatively reports in-progress even if expired or anomalous. The tool never expires sessions.

Only an object at least seven days old with a scoped project, historical same-organisation supervised context, no observed exact database reference, unchanged LIST/HEAD ETag-size-time and expected source/project/checksum metadata reaches `NO_DATABASE_REFERENCE_OBSERVED_REVIEW`. HEAD does not verify audio bytes or metadata authenticity. Missing context, changed bytes, unknown timestamps, failed HEAD and provenance uncertainty remain unverified/review-only. A database or listing failure aborts the report, and the command redacts dependency errors. NoSuchKey is not historical proof of erasure.

Per-object output contains only fingerprints and classifications, not raw keys, project IDs, exact recording sizes/times, audio bodies, names, checksums, metadata or signed URLs. The selected organisation, report observation time and opaque page cursor remain in the restricted envelope. `disposalCandidates` is always false. These reads are not an atomic database/storage snapshot; even repeated results cannot prove disposal is safe. There is deliberately no stable-orphan or deletion-candidate classification.

This slice excludes unreferenced render outputs, other product prefixes, deleted-organisation prefixes and missing database rows not represented by the listed objects. It does not validate production R2, legal holds, retention, residency, backups, recovery targets or physical C8 LAN/TLS/offline acceptance. Fictional unit storage and disposable CI PostgreSQL tests are the intended validation environment. All Inside PRs remain Draft; production deployment and migrations are prohibited by the current task.
