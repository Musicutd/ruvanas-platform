# C9 AudioLab quarantine and multipart inventory — Draft-only

This is a **read-only evidence report**. It does not delete a completed object, abort a multipart upload, read audio bodies, alter a database row, or establish a lawful disposal decision. Do not run it against production until its database/R2 read scope, report handling and operator are separately approved. No production storage scan was performed while developing it.

AudioLab starts a multipart upload under `quarantine/{organisationId}/audio-lab/{projectId}/{uuid}.{ext}` and records the exact key and upload ID in `SchoolAudioUploadSession`. A process failure can leave either a completed quarantine object or an unfinished multipart upload. The command `npm run audit:studio-audio-uploads -- --organisation-id=<id>` compares one bounded page of each storage class with exact database sessions, global media references and current project privacy. It checks old completed objects with HEAD and their `quarantine=true`/project metadata. It never uses HEAD to claim the size or contents of an unfinished multipart upload. [Cloudflare documents `ListMultipartUploads` as supported by R2](https://developers.cloudflare.com/r2/api/s3/api/); live behaviour with this account remains unverified.

Each section reads up to 100 entries by default, or `--limit=<1–200>`. `pages.quarantine.nextCursor` can be supplied as `--quarantine-cursor=<value>`. `pages.multipart.nextCursor` can be supplied as `--multipart-cursor=<value>`. Multipart cursors encode the raw key and upload ID for pagination; **encoding is not encryption**. Treat reports and cursors as restricted operational data, not public CI output. The report contains key/upload fingerprints rather than raw identifiers in its ordinary items. It always says `coverage: BOUNDED_PAGE_ONLY`, with independent `hasMore` flags. A final page alone is not a complete organisation inventory, and live listings can change while pages are read.

Only items with a valid storage timestamp at least seven days old, an existing ordinary project, no conflicting media reference, no mismatched session and no unsettled session receive `OLD_QUARANTINE_OBJECT_REVIEW` or `OLD_MULTIPART_UPLOAD_REVIEW`. Those labels mean **review**, not orphan proof or deletion approval. Quarantine objects also require unchanged LIST/HEAD attributes and expected metadata. Missing sessions can reflect a lost transaction or deleted historical rows; they do not prove an object is disposable. Sessions marked initiated, uploading or completing remain unsettled even after expiry. A private Corrections project, cross-tenant or mismatched session, exact MediaAsset reference, recent item, uncertain timestamp or failed HEAD cannot receive an old-item review label. Truncated pagination can still report old items on the current page, but never establishes complete organisation coverage.

This slice does not cover deleted-organisation prefixes, other products' quarantine paths, live R2 races, legal holds, retention approval, storage backup evidence or actual disposal. It complements the [direct Studio output inventory](corrections-c9-studio-storage-inventory.md); neither report should be wired into the operations worker as an automatic sweep. A future disposal design requires a separate human-authorised path and a fresh lock/reference check immediately before any mutation.
