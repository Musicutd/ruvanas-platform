## 2 October follow-up edge-case work — local evidence, not yet CI

The working-tree follow-up after `2ba3c7f` adds a Corrections-specific lock and source-state recheck to staff render-only submission. It shares AudioLab's project/media/take lock order, so a permanent-delete transaction and its post-commit object cleanup cannot race a new Corrections submission into Guard. Missing or deleted source media and trashed or permanently deleted takes are rejected. Ordinary Studio approval and other product handoffs are unchanged. A new disposable-database concurrency case exercises the lock directly; it does not exercise the full `submitCorrectionsProgramme` API, and it has **not** run in GitHub CI yet.

The external broadcast review found no documented provider disconnect or shutdown-acknowledgement contract. Ending a session, removing Studio Pro access, or disabling a Super Admin destination profile now preserves the last observed external connection state and warns that provider shutdown is unconfirmed. The operations worker counts ended sessions with external links conservatively, including a connect call that may have succeeded before its database success write. This is detection, **not** cutoff: the worker currently logs an aggregate count, there is no provider-confirmed resolution/clear workflow, and an operator must inspect the provider separately. Do not treat a local `ENDED` or disabled profile as proof that external audio stopped. This remains a release blocker.

A disposable-database public-player case now checks that an ended zone assignment and `CLOSED` Corrections location still leave the historically assigned station private, including previously issued listener authority. The current predicate includes inactive assignments and closed facilities. It relies on retaining the CorrectionsFacility marker and assignment history; there is no application facility-delete route, but legacy/manual data changes and actual historical customer rows still need an audit-aware review before release.

Local checks on the follow-up work: **1,011 unit tests passed, 8 skipped, 0 failed**; product registration/catalogue checks **37 passed** (seven families, 35 public tiers); static integrity checked **1,481 files**; Prisma schema validation and Client generation passed using a dummy local connection string that contacted no database; `next build` exited 0 with the existing Studio CSS warning and missing local `DATABASE_URL` messages during static-page generation. `test:acceptance` did not run locally because its isolated server URL was not configured. New disposable-database route and concurrency cases remain **unverified until GitHub CI**. No production database or customer data was touched.

## Control boundary

The existing six product families must retain their normal Studio, catalogue, entitlement, navigation and playout behaviour. Inside must remain behind its product entitlement and permissions; contributor submission is not approval, ordinary Studio handoff is unchanged, and offline players must not be counted as delivered. Priority/Emergency and return-to-current-private-programme claims need independent end-to-end evidence for the intended release. No public or unrelated audio is an acceptable fallback for a private Corrections facility.

This ledger may be updated only with attributable evidence for the exact commit and environment under review. A local test result is not a production verification. Even when every row has evidence, a human release decision is still required; this document cannot trigger a deployment or migration.
