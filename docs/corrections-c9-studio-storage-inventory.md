# C9 Studio audio storage inventory — Draft-only operator guidance

This is a **read-only evidence report**, not an orphan-deletion tool or a release gate pass. Do not run it against production until the storage and database read scope, handling of the resulting report, and operator are separately approved. No production scan was performed while developing it.

The AudioLab completion path copies a validated recording to `organisations/{organisationId}/school-audio/{projectId}/{uuid}.{ext}` before committing its MediaAsset and AudioTake rows. A process death in that gap may leave an object with no media row. The old upload-session schema does not store that final object key, so historical objects cannot be deterministically attributed to a submission or proven safe to erase. Older AudioTake tombstones with a null `purgeAfter` marker may also still have bytes in storage. Both cases require human review.

The command `npm run audit:studio-audio-storage -- --organisation-id=<id>` reads one bounded page (100 objects and 100 old tombstones by default; maximum 200 each) for exactly one organisation. It lists only the direct AudioLab final-key shape, excludes render outputs, checks exact MediaAsset keys across all tenants and statuses, checks current project privacy and active upload sessions, and verifies shortlisted objects with a HEAD request. It does not read audio bodies. The report contains SHA-256 key fingerprints, not raw object keys, and has a run ID, observation time, classifications, counts and continuation cursors. Use `--limit=<1–200>`, `--final-cursor=<nextCursor>` and `--legacy-after-id=<nextAfterId>` to continue a page. Each section has a `hasMore` flag. A report always states `coverage: BOUNDED_PAGE_ONLY`; even a last page is not by itself a complete tenant inventory. The operator must separately account for every page and the excluded storage classes.

Only objects at least seven days old can reach `UNREFERENCED_REVIEW`; all other states are retained or marked unverified. A second run of the **same page** at least 24 hours later may use `--previous-file=<restricted-prior-report.json>` to mark unchanged observations as `STABLE_UNREFERENCED_REVIEW` or `STABLE_LEGACY_TOMBSTONE_REVIEW`. Even stable observations are **not** deletion approval: the two reads are not an atomic lock on the object or database, and an older final key has no durable upload-session association. Keep reports in a restricted operator location; do not post them to public CI logs or a pull request.

The scanner has no delete, abort, database update or production deployment mode. A missing or changed project, Corrections-private project or media-asset association, mismatched key/project, active upload, missing/changed timestamp, mismatched provenance, failed HEAD, or database/storage failure never becomes a positive cleanup decision. Referenced MediaAssets remain referenced even when their status is `DELETED` or their organisation is malformed. A legacy tombstone with an observed missing object is reported as an observation, not as proof that storage was erased in the past.

This first slice does **not** enumerate abandoned quarantine objects, incomplete multipart uploads, deleted-organisation prefixes, or every other product's storage path. It has not been exercised with live R2 credentials or production data. A future disposal design needs legal/retention approval, protected-media backup evidence, durable session-to-final-key pinning for new uploads, a fresh lock-and-reference check, and a separate human-authorised execution path. Do not add an automatic sweep to the operations worker based on these reports.
