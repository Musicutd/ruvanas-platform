## Release constraints visible at audit

- The previous Studio update already implements STP.1–STP.12 foundations, but this specification adds STP.7A and expands STP.8A acceptance. Earlier test evidence is not evidence for these new requirements.
- The existing Studio external broadcast worker remains provider-neutral. Latest `main` has a separate, station-scoped Online Radio encoder that is proven only for its configured Centova AutoDJ rotation; it must not be mistaken for the Studio Manual Playout bridge or a general external-destination provider. Production Studio Icecast/SHOUTcast delivery requires compatible encoder infrastructure, secrets and integration tests. A saved destination profile is not proof of live transport.
- `StudioPlayoutSession` is not consumed by `lib/player-programming.js` or `lib/player-manifest.mjs`. Manual queue transitions therefore record control state but do not by themselves switch the listener/player manifest to that item. The Console must not call such a state "verified on air". A priority-aware output bridge, playback proof, real rights recheck and live/fallback exercise are required for a full release.
- Browser Live Studio similarly requires a compatible real-time media provider before microphone output can go on air.
- The local worktree has no disposable PostgreSQL service or media provider. Unit/build verification is available; live end-to-end acceptance must be recorded as unverified until a disposable environment is supplied.
- The existing dirty `codex/subscriber-ux-retail-signage` checkout was preserved. This task uses a separate clean worktree based on the latest verified `main`.
