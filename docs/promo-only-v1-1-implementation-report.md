# Promo Only automatic catalogue sync — v1.1 testing build report

Status at implementation review: completed and verified locally, without a real Promo Only account or production approval. Deployment status must be checked separately in Render. The attached v1.1 specification supersedes earlier concepts. This report describes the code, not a claim of commercial distribution rights.

1. **Existing Ruvanas components reused.** Global `RUVANAS_CATALOGUE` media assets and tracks, `MediaGenre`/`MediaAssetGenre`, protected catalogue audio storage, provider-neutral distributor connection/track/release/sync records, the operations worker, `AuditLog`, Super Admin role gates, `resolveEntitlements`, `musicTrackEligibility`, generated/subscriber playlists, AutoDJ and Studio Manual Playout.
2. **Architecture.** One Promo Only connection feeds discovered RSS and authenticated metadata into the existing master catalogue; a separately authorised import can create one protected global media asset/track. Subscriber selection uses existing Ruvanas tier and rights policy. No tenant copies, provider download controls or subscriber credentials were added.
3. **Files created.** `lib/promo-only.mjs`, `lib/promo-only-client.mjs`, `lib/promo-only-service.js`, `lib/promo-only-download-service.js`, `lib/provider-genre-service.js`, `lib/catalogue-playback-include.js`, `/admin/promo-only` UI, `/api/admin/promo-only` routes, `/api/catalogue/music/route.js`, the Prisma migration, focused tests, this report and the operator guide.
4. **Files changed.** Prisma schema and package lock (`saxes` XML parser), master catalogue admin page, generic distributor routing/worker exclusion, operations worker, catalogue storage, track eligibility and subscriber playlist, generated playlist, player programming, AutoDJ, radio-clock/advanced scheduler, Studio readiness, subscriber simple nonstop, admin navigation, and `.env.example`.
5. **Database migration.** `20261124000000_promo_only_testing_sync` adds provider feed items, genre mappings/provenance, track catalogue provider/tier/release fields, distributor metadata/import/audio state and sync run metrics. Prisma schema validates and client generation succeeds. The SQL was **not applied to a production-like PostgreSQL database**; migration execution remains a release gate.
6. **Super Admin catalogue.** Existing `/admin/catalogue` displays provider metadata-only records and imported protected tracks, including IDs, mix/BPM, source/canonical genre, status and tier. Its genre cards now show provider provenance, original value, status and links. `/admin/promo-only` provides manual sync, test import, refresh, tier, quarantine, rights enable and genre controls.
7. **Subscriber catalogue.** `GET /api/catalogue/music` provides a bounded, authenticated, tenant-context list of currently eligible licensed tracks with optional channel/search/genre filters. Its explicit DTO contains track labels, IDs, genre, BPM, duration, explicit flag and tier, **not** tokens, media keys, provider responses or download URLs. Existing subscriber playlist/AutoDJ paths reuse the same global tracks.
8. **Tier entitlement.** `Track.minimumCatalogueLevel` and canonical genre level are checked against the active plan on the server. Product use, territory, rights review, expiry, active provider and approved genre remain independent gates. Provider imports default to no product uses or territory; a Super Admin must explicitly enter contractual uses and territories before enabling. Region-limited provider tracks fail closed when a channel has no territory.
9. **Download authorization.** Both the endpoint and import service check Super Admin/AUDIO_TEST/feature flag before a provider request; the service checks again before database access. Queue acceptance must identify the same track and audio media type. Only the privileged backend holds credentials. A normal subscriber, tenant admin, DJ or pillar user is denied server-side.
10. **Promo Only API.** Server-only token acquisition uses Basic API key/secret with user ID and an expiring cache. Calls use the documented Bearer encoding. Track/release/date metadata, queue, available-server ID, bounded media fetch and success acknowledgement have safe timeouts/retries and host rules. Official [token](https://api.promoonly.com/doc/token), [track](https://api.promoonly.com/doc/track_info), [queue](https://api.promoonly.com/doc/queue_download), [server](https://api.promoonly.com/doc/download_servers), [file](https://api.promoonly.com/doc/download_file), [success](https://api.promoonly.com/doc/download_success) references are linked here; actual account responses have not been exercised.
11. **RSS integration.** Server-side HTTPS feed with conditional ETag/Last-Modified requests, byte limit, real XML parser, entity decoding, DTD/entity declaration refusal and stable idempotency keys. A run fails visibly rather than silently truncating a feed over 250 entries. DISCOVERY makes no authenticated API or audio calls. The existing operations worker polls due integrations under a database lease; METADATA enriches at most 25 pending items per run.
12. **Genre synchronisation.** Authenticated API genre is source authority; original text remains on distributor track and mapping. Canonical matching uses normalized space/case/name/slug; unknown genres can be auto-created with `PROMO_ONLY` provenance, optional pending review, and Premium default. Super Admin can approve, rename, alias, remap, merge, activate/deactivate. No genre is automatically deleted on feed absence.
13. **Duplicate prevention.** `(provider, normalizedSourceGenre)` and `(connectionId, externalTrackId)` are unique; feed idempotency keys and protected audio checksums prevent repeated source records. A stored-but-unlinked file becomes a reconciliation item, not a blind repeat download.
14. **AutoDJ integration.** Approved tracks are candidates through the existing music-mode and playlist eligibility; importing alone leaves them Draft and not AutoDJ-ready. Existing policy priority and no-dead-air logic are untouched. Subscriber simple nonstop now can consider rights-approved Licensed Catalogue in Online Radio too, subject to the same product-use/territory/tier checks.
15. **Environment variables.** `PROMOONLY_ENABLED`, `PROMOONLY_MODE`, `PROMOONLY_RSS_URL`, `PROMOONLY_POLL_MINUTES`, `PROMOONLY_USER_ID`, `PROMOONLY_API_KEY`, `PROMOONLY_API_SECRET`, `PROMOONLY_AUDIO_DOWNLOAD_ENABLED`, `PROMOONLY_ALLOW_HTTP_MEDIA_TEST`, `PROMOONLY_DOWNLOAD_ROLE`, `PROMOONLY_MAX_DOWNLOADS_PER_RUN`, `PROMOONLY_AUTO_CREATE_GENRES`, `PROMOONLY_GENRE_REVIEW_REQUIRED`, timeout/retry/size settings and optional exact media hosts. All default off or safe; no secrets in the repository. Bare media hosts use HTTPS unless an explicit isolated-testing HTTP exception is configured. See `.env.example`.
16. **Tests added.** `tests/promo-only-testing.test.mjs` exercises mode gates, safe configuration, RSS entities/unsafe XML, field mapping, token refresh, server allow-list and ID, HTTPS-by-default/explicit HTTP test transport, acknowledgement route/form, roles, tier, genre, idempotent discovery→metadata, metadata-change reconciliation, migration structure and static route boundaries.
17. **Results.** `npm test`: **852 total, 844 passed, 8 pre-existing skips, 0 failed**. `npm run ci:static`: passed. `prisma validate` and `prisma generate`: passed. `npm run build`: exit 0 with compilation/type/lint/static-page phases; the build logged authentication warnings because a placeholder local PostgreSQL URL was supplied. `git diff --check`: passed. No live DB or provider integration test was possible without approved credentials.
18. **Subscriber-download security evidence.** Pure authorization tests reject subscriber, client admin, pillar admin, DJ/presenter, school admin and ordinary roles; endpoint source checks enforce Super Admin before calling the service; service source check is before database/provider work. The new subscriber catalogue route returns an explicit safe DTO. This is local automated evidence, not a penetration test against deployed infrastructure.
19. **DISCOVERY.** After test migration and feed approval, configure `PROMOONLY_ENABLED=true`, `PROMOONLY_MODE=DISCOVERY`, vetted `PROMOONLY_RSS_URL`; use the existing operations worker or Super Admin **Run Sync Now**. Review feed item counts, statuses and safe error codes in `/admin/promo-only`.
20. **METADATA.** Add server-only user ID/API key/API secret, set `PROMOONLY_MODE=METADATA`, sync and review metadata, provenance, new genres and tier mappings. No audio download is allowed in this mode. Previously discovered feed items are enriched in subsequent bounded runs.
21. **AUDIO_TEST.** Only with agreed API distribution and approved media-use/storage rights, set `PROMOONLY_MODE=AUDIO_TEST` plus `PROMOONLY_AUDIO_DOWNLOAD_ENABLED=true`; a Super Admin selects one audio item, reviews the protected draft and explicitly records licence reference, product uses and territory before enabling. Keep Centova/stream setup separate. Promo Only’s documented media URL is HTTP, while this build tries HTTPS by default and blocks a silent HTTP fallback. Confirm HTTPS support or formally review the isolated-testing HTTP exception first.
22. **Remaining limitations and release gates.** No real feed or credentials, provider entitlement or audio download was tested; actual RSS format may need adapter adjustment. The 250-item testing feed limit, 25-item metadata batch and one-at-a-time audio import are deliberate; `PROMOONLY_MAX_DOWNLOADS_PER_RUN` does not implement an automated batch. A provider metadata change pauses playback for manual reconciliation. Migration execution, database rollback rehearsal, real provider responses, rights-contract interpretation, UI/browser checks and tiered listener-output verification remain. `PRODUCTION` is hard-locked; enabling commercial distribution requires a separate licensed release decision.
